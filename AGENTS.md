
### Untitled.ipynb
1. **Remote data load**: `pd.read_csv("https://www.football-data.co.uk/new/BRA.csv")` — requires internet.
2. **Column pruning (cell 9)**: keeps only `['Date','Season','Home','Away','HG','AG','Res','PSCH','PSCD','PSCA']`.
3. **dropna() (cell 10)**: drops ~244 rows with missing Pinnacle odds → 5275 rows remain.
4. **Date parsing**: `pd.to_datetime(df_raw['Date'], format='%d/%m/%Y')`, then sorts by `Date_parsed`.
5. **Feature engineering** (cells 17–34):
   - Odds → implied probabilities, juice‑removal, `dif_prob = p_home - p_away`
   - `goal_diff`, `goal_total`
   - `bucket_favoritismo` — quantile‑based 7‑bucket categorization of `dif_prob`
   - `home_last5_goals`, `away_last5_goals` — rolling mean of goals (per‑team, shifted)
   - `home_last5_concede`, `away_last5_concede` — rolling mean of conceded goals
   - `home_ewma_5_goals`, `away_ewma_5_goals` — exponential moving average (span=5)
   - `Res_num`: H→2, D→1, A→0
   - `home_last5_winrate`, `away_last5_winrate` — rolling win% (home = Res_num==2, away = Res_num==0)
   - `home_points`, `away_points` — 3/1/0 points
   - `entropy` — normalized Shannon entropy of implied probabilities (base‑2, 0–1)
   - `ret_home`, `ret_draw`, `ret_away` — bettor return (odds − 1 if hit, else −1)
6. **Final export**: `df_raw.to_csv("dados_processados.csv", index=False)` runs at the end. This regenerates `dados_processados.csv`.

### analise_descristiva.ipynb

## Feature engineering gotchas

### Chronological order required
All rolling/EWMA features use `.shift()` before aggregating. The notebook sorts by `Date_parsed` in cell 16, but **only after column pruning and dropna**. If adding new features that depend on temporal order, verify the sort is still in effect — or re-sort before every rolling operation.

### First 5 rows per team are NaN
Rolling features with `min_periods=1` give non‑NaN values from row 1, but EWMA features (cell 28) have `EWMA without min_periods` and produce NaN until the warm‑up period. When saved to CSV, these appear as empty fields. On read-back (analise_descristiva.ipynb), they become NaN — this is expected.

### Bug: `home_last5_ppg` uses wrong column
In `Untitled.ipynb` cell 32, `home_last5_ppg` is computed by grouping on `"Home"` but aggregating `["away_points"]` instead of `["home_points"]`. This means home PPG is actually calculating away PPG for the home team (their own scoring *as a visitor* in prior matches), which is a different statistic. Not used in the EDA notebook, but fix before modeling.

### Date only (no Time)
The notebook keeps `Date` (dd/mm/yyyy) but **drops `Time`** during column pruning (cell 9). If you need intra-day ordering for same-date matches, keep `Time` in the selection list and parse it:
```python
df['time'] = pd.to_timedelta(df['Time'] + ':00')
df['datetime'] = df['date'] + df['time']
```

### Leakage risk
All rolling features use `.shift()` to avoid look-ahead bias. When adding similar features to the pipeline, always call `.shift()` before rolling/EWMA aggregation. The bucket `bucket_favoritismo` uses current-match `dif_prob` — this is not leakage for a pre‑match prediction, since odds are known before kickoff. If you add any post‑match metrics (actual points, actual goals) as predictive features, they MUST be shifted.

Analysis of Brazilian Série A football matches (2012–present). Features are built to support models predicting match outcomes (H/D/A) using pre‑match Pinnacle odds and team form metrics.
